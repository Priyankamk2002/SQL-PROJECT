# Grocery Store Management – SQL Database Analysis

## Project Overview
This project simulates a **mini grocery store database** where various entities such as **products, suppliers, customers, employees, and orders** interact.  
The goal is to design a **relational database** and perform **SQL-based data analysis** to derive business insights.

---

## Domain Knowledge
The retail and grocery domain involves managing:

- Inventory and product categories
- Suppliers
- Customers and their orders
- Employees

Effective data management helps businesses:

- Track sales and revenue
- Monitor product availability
- Analyze customer and employee activity
- Improve operational efficiency

---

## Database Structure & Relationships

| Relationship | Type |
|--------------|------|
| Supplier → Products | One-to-Many |
| Categories → Products | One-to-Many |
| Products → Order_Details | One-to-Many |
| Orders → Order_Details | One-to-Many |
| Customers → Orders | One-to-Many |
| Employees → Orders | One-to-Many |

**Design Notes:**

- Use **AUTO_INCREMENT** for primary keys.
- Use **FOREIGN KEY constraints** with `ON DELETE CASCADE` and `ON UPDATE CASCADE`.
- Ensure CSV column names match **table column names** while importing data.

---

## Project Objectives

1. Design and implement a relational database for a grocery store.
2. Retrieve and manipulate data using SQL queries.
3. Perform business analysis: top customers, best-selling products, revenue trends.
4. Practice joins, aggregations, subqueries, and filtering techniques.

---

## Analysis Questions & SQL Tasks

### 1. Customer Insights
- How many unique customers have placed orders?
- Which customers have placed the highest number of orders?
- Total and average purchase value per customer.
- Top 5 customers by total purchase amount.

### 2. Product Performance
- Number of products in each category.
- Average price of products by category.
- Products with highest total sales volume (quantity).
- Total revenue generated by each product.
- Product sales by category and supplier.

### 3. Sales and Order Trends
- Total orders placed.
- Average value per order.
- Dates with the most orders.
- Monthly trends in order volume and revenue.
- Weekday vs weekend order patterns.

### 4. Supplier Contribution
- Total number of suppliers.
- Supplier with the most products.
- Average product price per supplier.
- Suppliers contributing most to total product sales (revenue).

### 5. Employee Performance
- Employees who processed orders.
- Employees handling the most orders.
- Total sales value per employee.
- Average order value per employee.

### 6. Order Details Deep Dive
- Relationship between quantity ordered and total price.
- Average quantity ordered per product.
- Unit price variation across products and orders.

---

## Challenges
- Understanding table relationships and using correct joins.
- Ensuring data consistency with foreign key constraints.
- Handling aggregation across multiple joined tables.
- Extracting time-based trends when dates are stored as VARCHAR.

---

## Tools & Techniques

- **SQL Techniques:** `JOIN`, `GROUP BY`, `SUM`, `AVG`, `COUNT`, subqueries
- **Analysis:** Customer segmentation, product/supplier performance, time-based trends, employee performance evaluation
